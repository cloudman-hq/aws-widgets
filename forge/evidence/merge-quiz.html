What changed

Secret boundary

One installation-scoped KVS secret, server-only legacy import with STS validation before write, strict resolver authorization/input schemas, safe envelopes, and allow-listed logs.

AWS adapters

Server-only SDK v3 clients for EC2, S3, Lambda, ECS, and DynamoDB. Results are normalized; pages/items/time/retries are bounded.

Custom UI

Global settings, macro configuration, and macro view cover loading/success/all public errors, accessible status/focus, safe raw bridge failures, and retry only when allowed.

Adoption path

The Forge app ID stays unlisted in development while the manifest adopts com.aws.widget.confluence-addon and preserves macro key aws-widget-macro.

Deviations and open gates

  • The approved implementation uses installation-held Forge secrets, with an adapter boundary for future federation.
  • Forge rejected --personal registration in developer spaces; the app is instead a normal unlisted app in a dedicated AWS Widgets developer space.
  • PR CI omits authenticated Forge lint so no long-lived Forge credential is stored in GitHub.
  • Project-scoped Playwright failed closed because the repository has no profile declaration. Browser Custom UI/editor evidence remains open; no browser-profile fallback was used.
  • The real-site rehearsal proves platform identity and data continuity, but not browser execution, credential import, or a successful AWS resource result.
  • No real AWS success, production adoption, Marketplace submission, merge, or Connect retirement is included.
