Forge production release review

AWS Widgets · stylesheet CSP fix · pipeline-only deployment remediation

Outcome

Technical verification passed

The production settings page had a complete theme in source but rendered with browser defaults. Forge kept the dynamically-created <style> element in the DOM while refusing to attach a stylesheet under its production CSP.

Code correction

  • The existing theme moved from a JavaScript template string to theme.css.
  • Each Custom UI entrypoint imports that CSS so Vite emits a relative external stylesheet.
  • Runtime style injection was removed from settings, macro configuration, and macro view mounting.
  • A build-artifact regression test requires all three generated pages to link a relative stylesheet containing the AWS theme.

Release-process correction

  • The initial production hotfix was deployed locally and therefore bypassed GitHub Actions.
  • deploy-prod.yml now validates the Forge subtree, uploads the verified forge/dist artifact, and makes production deployment depend on both legacy and Forge checks.
  • The existing GitHub production environment approval gate now protects both Firebase/Connect and Forge deployment in one job.
  • FORGE_EMAIL and FORGE_API_TOKEN are stored as production-environment secrets; values were not printed or committed.

Evidence

  • The regression test was observed failing before the implementation and passing afterward.
  • npm run verify: lint, typecheck, build, 23 tests, and Forge lint completed successfully.
  • Live production verification found one external stylesheet and the expected computed font, color, size, and zero title margin.
  • The workflow contract was parsed and checked with yq.

Forge lint still reports the existing deprecated backend-egress warning. It has zero errors and is unrelated to the stylesheet correction.
